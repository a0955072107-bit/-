## 0. 一句話標準

**買家打開預覽的前 5 秒，要覺得「這是專門為我這一行設計的」，而不是「一個換了顏色的通用模板」。**
每一款都要有一個記得住的東西（只要一個），其他地方安靜、整齊、好讀。

---

## 1. 動手前：先寫設計計畫（5～10 行就好）

每款新模板開工前，在 PR 描述或工作筆記寫下：

1. **對象與任務**：誰會看（例如「50 歲、要帶小孩看牙的家長，用手機」）、這頁最重要的一件事（例如「預約」）。
2. **配色**：4～6 個有名字的色票（hex）。
3. **字體**：標題／內文各用什麼、為什麼適合這一行。
4. **版面概念**：一句話 + 簡單 ASCII 線框（首屏、主要區塊順序、對齊方式）。
5. **記憶點**：這款唯一大膽的地方是什麼（例如「首屏就是今日門診看板」）。
6. **自我檢查**：拿一個類似的題目想一下，如果會得到差不多的結果，就是「預設值」不是「選擇」，改掉它並寫下改了什麼。

## 2. 品質標準與檢查清單

每一項都要能回答「有／沒有」。交付前逐條打勾。

### 2.1 排版與層級
- [ ] 首屏（1280×800 不捲動）看得到：大標題、一句說明、主要按鈕；手機（390×844）也要看到主要按鈕，不能被底部固定列蓋住。
- [ ] 首屏標題：中文 8～16 字、英文 3～8 個字。說明文 1～2 句。
- [ ] 每個區塊只有一個重點；區塊開頭不要每次都是同一個「左對齊 h2 + 灰色說明」公式，至少有 2～3 種區塊開場方式（例如大圖帶標題、表格直接當主角、引言）。
- [ ] 內文行長：中文每行 ≤ 40 字（約 `max-width: 36em`）、英文 ≤ 75 字元。
- [ ] 對齊一致：一個區塊裡不要左對齊和置中混用。置中只用在短文字（標題、CTA 區）。
- [ ] 結構裝飾（編號、框線、標籤）要「帶資訊」：只有真的是步驟／時間序才用 01／02／03。

### 2.2 字體搭配
- [ ] 最多兩個字族（中文一套＋拉丁一套算一組）。兩套要明顯不同（例如襯線標題＋無襯線內文），不要兩個很像的無襯線。
- [ ] 字級比例固定（建議 1.25 或 1.333），寫成變數或 clamp()；全站不超過 6 個字級。
- [ ] 內文 16～18px；行高中文 1.75～1.9、英文 1.55～1.65；襯線內文行高再加一點。
- [ ] 標題行高 1.15～1.3；中文標題 `letter-spacing: 0`，英文大標可微負（-0.01～-0.02em）。
- [ ] 不要每次都選同一組（目前已經很多款用 Fraunces、Plus Jakarta Sans）。新款先列 3 個候選再選，並在設計計畫寫理由。
- [ ] 數字欄位（價格、時間表）加 `font-variant-numeric: tabular-nums`。
- [ ] 英文版用 `…` 而不是 `...`、用彎引號 “ ”；店名等專有名詞加 `translate="no"`。

### 2.3 配色
- [ ] 色票 4～6 個：底色、表面色、文字、次要文字、品牌色、（輔助色）。功能色（營業中、休診）另計。
- [ ] 60／30／10：底色系佔大部分，品牌色只用在按鈕與少數重點，不要整頁都是品牌色。
- [ ] 文字對比 WCAG AA（內文 4.5:1、大字 3:1），**按鈕文字也要算**；muted 色要在 surface 與 bg 上都測過。
- [ ] 狀態不能只靠顏色（營業中／休診要有文字）。
- [ ] 跟同行業前一款要明顯不同（不是只換色相）。

### 2.4 間距節奏
- [ ] 用一組間距階梯（例如 4／8／12／16／24／32／48／72／112px），不要出現 13px、27px 這種隨手值。
- [ ] 區塊上下留白大於區塊內元素間距的 2 倍以上，讓「區塊之間」和「區塊內」一眼分得出來。
- [ ] 相關的東西靠近、不相關的分開（標題離下方內容近、離上一區塊遠）。
- [ ] 卡片內距與卡片間距一致；同一層級的元件圓角一致，**不同層級可以不同**（大容器圓角大、小標籤圓角小）。

### 2.5 手機版
- [ ] 360px 無水平捲軸（SPEC 已規定），390px 實際截圖看過。
- [ ] 點擊目標 ≥ 44×44px（語言選單 ≥ 32px，SPEC 規定）。
- [ ] 底部固定列：最多 2 個按鈕，主要那個比較寬；body 留出它的高度；不要蓋住表單送出鈕或頁尾最後一行。
- [ ] 手機版要「重新排版」而不是「全部疊起來」：6 張以上同型卡片在手機改成 2 欄小卡、清單、或水平捲動，避免一區塊超過 3 個螢幕高。
- [ ] 寬表格（門診表）在手機提供不需要橫向捲動的替代呈現（例如只顯示今天＋可展開），或至少第一欄固定（`position: sticky`）。
- [ ] 全頁手機高度參考值：≤ 7000px（390 寬）。超過就檢查是否有區塊可以收合。
- [ ] `touch-action: manipulation`；不要 `user-scalable=no`。

### 2.6 無障礙
- [ ] 語意標籤、標題不跳級（SPEC 已規定）；加「跳到主要內容」skip link。
- [ ] 所有可互動元素有 :hover、:active、:focus-visible，focus 不能被固定頁首蓋住（`scroll-padding-top`）。
- [ ] 表單：每個欄位有 label、正確 `type`／`inputmode`／`autocomplete`；placeholder 是範例格式；錯誤訊息寫在欄位旁。
- [ ] 動畫遵守 `prefers-reduced-motion`；無限循環動畫（例如蒸氣）在 reduce 時要停。
- [ ] 圖示按鈕有 `aria-label`；裝飾性 SVG 有 `aria-hidden="true"`。
- [ ] 動態更新的內容（今日門診、營業中）用 `aria-live="polite"`。

### 2.7 效能
- [ ] Google Fonts 只載入真正用到的字重（每個字族 ≤ 3 個字重），加 `display=swap` 與 preconnect。
- [ ] 中文字型很大：標題可以用襯線中文，但內文優先用系統字型備援鏈，避免首屏等字型。
- [ ] 只對 `transform`、`opacity` 做動畫；不要 `transition: all`（SPEC 已規定）。
- [ ] 換成真實照片時的說明要寫：`<img>` 加 `width`／`height`、首屏圖 `fetchpriority="high"`、其他 `loading="lazy"`。（在圖片 CSS 註解裡提醒買家。）
- [ ] 單一 HTML 檔目標 ≤ 60KB（不含字型）。

### 2.8 多語排版
- [ ] **中文**：`lang` 正確（zh-Hant／zh-Hans）；字型鏈各自正確（TC／SC 不要混）；標題用 `text-wrap: balance`，內文用 `text-wrap: pretty` 避免最後一行只剩一兩個字或只剩標點（例如「定）。」）。
- [ ] **日文**：`line-break: strict`；`word-break: auto-phrase`（支援的瀏覽器會照詞組換行）；標題用 `<wbr>` 或 balance；不加字距；全形括號與「〜」。日文版不要直接沿用中文字型（中日漢字字形不同），用 Noto Sans JP／Zen Kaku Gothic New。
- [ ] **英文／西文**：西文比英文長 20～30%，按鈕、導覽列、首屏標題要在西文版也測過不換行破版；`hyphens: auto` 只用在內文。
- [ ] 同一款四語版本的首屏高度要接近，不能某語言的按鈕被擠到首屏外。
- [ ] **語言選單**：用 `scripts/lang-menu.py` 的下拉（`<details>`，沒有 JS 也能用）；目前語言用字重或底線標示；每個語言用自己的文字寫（English、繁體中文、简体中文、日本語、Español）並加 `lang`；手機版放在漢堡按鈕旁邊、一直看得到。
- [ ] 日期、時間、金額若由 JS 產生，用 `Intl.DateTimeFormat`／`Intl.NumberFormat`，不要手寫格式。

## 3. 要避免的「AI 味」

SPEC.md 的 Hallmark 12 條是**最低限度**（機器檢查得到的）。下面是機器查不到、但買家一眼就看得出的「AI 生成感」：

1. **預設配色組合**
   - 奶油底（≈#F4F1EA）＋高對比襯線大標＋赤陶／陶土色重點（≈#D97757）。← 目前 restaurant 正是這組。
   - 近黑底＋單一螢光綠或朱紅重點。
   - 報紙風：細線、零圓角、密排欄位。
   這些不是不能用，但只有在「這一行真的需要」時才用，而且要寫進設計計畫說明為什麼。
2. **SaaS 卡片套組**：所有內容切成一樣大小的圓角卡片、全部同一個圓角、同一個淡灰陰影、背景加漸層暈染。← 目前 clinic 的診療項目、醫師團隊都是這個。
3. **大數字＋小標籤的數據列**（「2016 開業至今／4.8★ 千則評價」）：預設套路，除非數字真的是賣點。
4. **每個區塊都淡入上滑**：所有區塊同一種 fade-up，是最明顯的生成感。改成「只有一個精心安排的進場」（例如首屏一次），其他區塊不動或只有使用者觸發的動畫。
5. **每張卡片 hover 都上浮**：只有可點的東西才給 hover 回饋。
6. **模板通用裝飾**：大寫加寬字距小標、`A · B · C`、`文字 —— 片段`、等寬字體當小標籤、按鈕後加 `→`、標題只把一個字變色或斜體（Hallmark 已擋大部分）。
7. **空泛文案**：「打造你的…」「專業、用心、值得信賴」。改成具體、這一行才會說的話（看診前先說明費用、最後點餐時間、停車方式）。按鈕寫清楚會發生什麼：「LINE 預約掛號」而不是「了解更多」。
8. **假圖太抽象**：一塊漸層＋一個十字或圓圈。藝術佔位圖要讓人一看就知道這格「放什麼照片」（診間、醫師半身、料理俯拍），並且有構圖。
9. **對稱的兩欄首屏（左字右圖）＋浮動小卡**：每個行業都這樣。至少思考一次其他首屏形式（滿版圖＋文字疊放、資訊看板式、大字排版式、菜單即首屏）。
10. **把大膽分散在每個地方**：每區都有一點花樣＝沒有重點。大膽只用在一處，其他安靜。出門前照鏡子拿掉一件配件。

## 4. 交付前截圖檢查流程（每款每個語言都要做）

截圖與暫存檔都放在 scratchpad，不要進 repo。

1. **lint**：`bash scripts/lint-all.sh` → 0 頁有需要處理的 FAIL。
2. **截圖**（Playwright，`require('playwright')`，`chromium.launch()` 不帶參數）：
   - 桌機 1440×900 整頁、1280×800 首屏（不捲動）。
   - 手機 390×844：首屏一張 ＋ 每隔約 1700px 捲動截一張視窗畫面（整頁截圖在 390 寬太長，縮圖看不清楚，一定要看局部）。
   - 360×740 首屏一張（最窄手機）。
   - 截圖前把 `.reveal` 全部加上 `.in`，等 800ms 讓字型與動畫完成。
3. **自動檢查**（同一支腳本裡）：
   - `document.documentElement.scrollWidth <= 視窗寬`
   - console 沒有錯誤（`pageerror`、`console.error`）
   - 390 寬整頁高度（參考 ≤ 7000px）
4. **自己看過每張圖**，逐項回答：
   - 首屏 5 秒：看得出是什麼行業、什麼店、按哪裡預約嗎？
   - 有沒有空洞（grid 缺格）、孤字孤標點、按鈕被擠換行、文字貼邊？
   - 圖文比例：有沒有連續 2 個以上的區塊只有文字或只有同型卡片？
   - 手機底部固定列有沒有蓋住重要內容？
   - 對照第 3 節「AI 味」清單，中了幾條？
5. **四語抽查**：繁中、英文、日文、西文（若有）各截手機首屏，比較高度與換行。
6. 有問題 → 修 → 重新截圖。PR 描述附上「看過了哪些尺寸、修了什麼」。

可重複使用的截圖腳本範例（放 scratchpad 執行）：

```js
// node shot.js <輸出資料夾> templates/<slug>/index.html
const { chromium } = require('playwright'); const path = require('path');
(async () => {
  const [, , out, f] = process.argv; const slug = f.split('/').slice(-2, -1)[0];
  const b = await chromium.launch();
  for (const [name, w, h, full] of [['desktop',1440,900,true],['fold',1280,800,false],['m360',360,740,false]]) {
    const p = await b.newPage({ viewport: { width: w, height: h } });
    const errs = []; p.on('pageerror', e => errs.push(e.message));
    await p.goto('file://' + path.resolve(f));
    await p.evaluate(() => document.querySelectorAll('.reveal').forEach(e => e.classList.add('in')));
    await p.waitForTimeout(800);
    await p.screenshot({ path: `${out}/${slug}-${name}.png`, fullPage: full });
    console.log(name, await p.evaluate(() => [document.documentElement.scrollWidth, document.documentElement.scrollHeight]), errs);
    await p.close();
  }
  const m = await b.newPage({ viewport: { width: 390, height: 844 } });
  await m.goto('file://' + path.resolve(f));
  await m.evaluate(() => document.querySelectorAll('.reveal').forEach(e => e.classList.add('in')));
  const H = await m.evaluate(() => document.documentElement.scrollHeight);
  for (let y = 0; y < H; y += 1700) { await m.evaluate(y => scrollTo(0, y), y); await m.waitForTimeout(300); await m.screenshot({ path: `${out}/${slug}-m${y}.png` }); }
  await b.close();
})();
```

## 5. 現有模板評估（2026-11-25）

用本標準評 `templates/clinic` 與 `templates/restaurant`。**以下全部是「建議（待使用者決定）」，尚未修改。**
兩款都通過 SPEC 與 Hallmark，390／1440 沒有水平捲軸、console 無錯誤；以下是「更好看、更專業」層級的問題。

### 5.1 clinic（安和牙醫）

| # | 問題 | 建議（待使用者決定） | 影響 |
|---|---|---|---|
| C1 | 首屏右側佔位圖是一塊水藍漸層＋十字＋牙齒輪廓，看不出是「診間照片」；手機上它和「今日門診」卡片被擠到首屏下方，最有特色的今日門診反而看不到。 | 佔位圖改成有構圖的「診間」示意（診療椅、窗、燈的幾何形）；手機版把今日門診卡片移到按鈕下方、圖片之前，或縮成一行「今天：早診 林醫師 看診中」。 | 高 |
| C2 | 診療項目 6 張同尺寸圓角卡＋同陰影＋hover 上浮，是典型「SaaS 卡片套組」；手機上疊成 6 張大卡，約 3 個螢幕高。 | 改成 2 欄清單（圖示＋名稱＋一行說明，用細分隔線），或「常見需求」分組（我牙痛／我要洗牙／孩子看牙）。手機改 2 欄小卡或清單。 | 高 |
| C3 | 醫師團隊照片佔位是同一個「圓頭＋半圓身體」剪影，三張只換底色，略顯廉價。 | 改成較抽象但有質感的肖像框（例如拱形框＋柔光漸層、無人形），並在註解寫建議照片比例 4:5；資訊加「看診時段」連到門診表，才有資訊價值。 | 中 |
| C4 | 門診時間表在手機需要左右滑動（min-width 720px），長輩最常查的資訊最難用。 | 手機版改成「依星期分組的清單」或只顯示「今天＋明天」並可展開完整表；至少讓第一欄固定。 | 高 |
| C5 | 每個區塊開頭都是同一個公式（左對齊 h2＋灰色說明），全頁 6 次，節奏單調。 | 讓門診表或交通區用不同開場（例如表格本身當主角、地圖區用大地址字）。 | 中 |
| C6 | 所有區塊都淡入上滑，生成感明顯。 | 只保留首屏一次進場，其他區塊取消 reveal。 | 中 |
| C7 | 首屏特點「✓ 健保特約」用文字勾號，三項在手機換成兩行，第二行孤零零。 | 改成小 SVG 勾號並允許兩欄整齊排列，或縮成兩項。 | 低 |
| C8 | 缺 skip link；表單沒有（只有 LINE），但美國版買家常需要「線上預約表單」。 | 加 skip link；英文版考慮加一個簡短預約請求表單（姓名、電話、方便時段）。 | 中 |

| # | 問題 | 建議（待使用者決定） | 影響 |
|---|---|---|---|
| R1 | 配色＋字體正好是 frontend-design 點名的頭號「AI 預設」：奶油底 #f6efe3＋Fraunces 襯線大標＋赤陶色 #b4532a。 | 保留溫暖感但換掉這組：例如深橄欖／墨綠底色區塊＋米白、或醬油褐＋柚子黃；標題字換成較少見、有日式食堂感的組合（例如 Shippori Mincho／Zen Old Mincho 系列＋拉丁 Newsreader 等），並在封面同步。 | 高 |

| R3 | 「環境」相簿在 1440 寬右下角有一個空格（第 4 欄第 2～3 列沒有內容），看起來像壞掉。 | 調整 grid-template-areas 讓 5 張圖剛好填滿（或補第 6 張）。 | 高（看得出的瑕疵） |
| R4 | 料理佔位圖（盤子＋圓點）在首屏很顯眼，但看起來像插畫圖示，與「真實餐廳」的照片感落差大，買家較難想像換照片後的樣子。 | 讓佔位圖更像「攝影構圖」：俯拍比例、自然光的明暗漸層、桌面紋理，並減少卡通色點；或首屏改成滿版圖＋文字疊放，讓買家直覺知道放大張料理照。 | 中 |
| R5 | 「關於我們」三張特色小卡＋圖示，又是一組卡片套組。 | 改成一段文字裡的三行重點（不用卡片），或用一張大圖帶短句。 | 低 |
| R6 | 顧客好評 3 張一樣的卡片、五顆星、置中標題，非常常見。 | 改成一則大型引言＋兩則小字，或把評價放進菜單旁（招牌菜的評語）。 | 中 |
| R7 | 中文長句換行出現孤標點（菜單說明最後一行只剩「定）。」）。 | 內文加 `text-wrap: pretty`；日文版加 `word-break: auto-phrase`。 | 低 |
| R8 | 每區淡入上滑＋蒸氣無限循環動畫；蒸氣在 reduce motion 已被全域關掉，但多數區塊的進場可以省。 | 只保留首屏進場與蒸氣（作為唯一記憶點），其他區塊取消 reveal。 | 低 |

**建議優先順序**：R3（明顯瑕疵）→ C4、C1（手機可用性）→ C2、R1（AI 感最重的地方）→ 其他。
